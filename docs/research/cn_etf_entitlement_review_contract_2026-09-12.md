# 权益更正、结算与证据验证

当前已完成只读复核、补充成交证据、单项现金分红的离线权益修订、补款/退款及持续驱动验收。修订只能使用显式假设的合成事实，并检查原账本、原登记、完整回报及修订链的一致性；真实来源未认证。原登记与结算事件保留，可归因的分红故障按完整条件处置，其他停止保留。涉及折算旧单位、成交数量/价格撤改或多次公司行为级联的更正仍未实现。

## 已验证的现状

`OfflineOrderJournal.inspect_snapshot(path)`通过只读连接校验完整事件链，返回带序号、指纹的已提交快照。它不调用通常开账时的未决订单恢复，不把PENDING改为UNKNOWN，也不清除权益故障。其他写入者随后仍可推进账本，因此报告必须绑定该次序号与指纹；只读检查不是锁住账户或认证券商数据。

新增6个测试方法，覆盖未决订单保持、缺失文件不创建、并发未提交状态隔离、提交后可见、输出副本隔离、损坏事件链和未知版本拒绝。最终167项相关检查通过。首次测试中的SQLite清理连接遗漏已修正，失败日志保留。

## 接续所需证据

当前驱动的成交回报严格只有`order_id`、`fill_id`、`quantity`、`price`。新增证据协议需分别表达实际成交时间及其时区、回报接收时间、来源消息身份和修订关系、数量/价格基准、最终权益与结算依据。字段缺失时必须明确未知，不能从订单日期、本机入账时间或当前持仓反推。

公开接口可提供部分候选映射：迅投官方成交对象列有成交编号、时间、价格、数量、金额和柜台合同编号，但这次资料核对没有确认时间单位、时区或成交撤销/更正关系，也不代表选择了券商或取得使用权限。官网直接打开超时后只核对其官方域名的索引文本，没有执行任何接口调用。[迅投交易模块说明](https://dict.thinktrader.net/nativeApi/xttrader.html)

实施顺序及最初证据要求如下；当前完成范围见末尾：

1. 建立只读权益复核材料，引用原权益、相关回报、冻结事件规则及当前账本指纹；对无法归因的故障明确列出信息缺口，不生成虚假的确定更正量。
2. 冻结带来源及时间语义的合成成交证据格式。旧回报继续可重放，但不得被自动补全为已核实的新格式。
3. 用预先固定的反例验证重复/冲突修订、跨登记日、折算旧单位、已到账分红和多次公司行为。单个更正需同时核对现金、份额、应收和费用差额。
4. 证据和归因都齐备后，才设计追加式更正事务；保留原事件，避免改写旧订单单位。更正某一项不能清除其他权益、估值、操作者或风险停止。
5. 将恢复条件与具体证据绑定，再验证重启、竞争写入和提交失败。真实接口或账户使用仍按现有项目边界另行处理。

最初6个新测试属于检查入口，不计为更正功能完成。其所在推进批次连同容量阶段13个新方法共新增19个方法；后续复核工具新增测试另行记账。工程检查不增加正EV证据或真实向前模拟天数，整体人工成熟度仍约30%。[当前落地方案](etf_monetization_execution_plan_2026-09-11.md)

## 只读复核材料已实现

新增`build_corporate_action_review`及导出入口`scripts/run_offline_corporate_review.py`。同一个SQLite只读事务中先核验事件链，再取得冻结规则、账本状态及支撑事件；并发写入发生时仍引用原事务视图，输出序号和指纹不会与较新的回报混用。默认最多10,000个事件、1,600万字节事件载荷，报告内公司行为和关联记录合计最多25,000项；导出另逐块限制为3,200万字节。超过限额直接报错并保留已有报告，不截断成一份看似完整的材料。批量登记事件只在对应公司行为内展示其相关字段，明确指纹引用完整原事件；活动订单只列核心账目字段，避免重复整批权益或全部准入报价上下文。

每项公司行为列出原登记权益、应收/已到账或已折算状态、支撑入账事件、尚未处理的回报和活动订单。只有登记之后记录、证券相同且订单日期可能涉及登记期的成交才列为候选，仍明确缺少真实成交时点、来源修订及单位证据。登记前成交和其他证券回报不会误入；同一迟到成交可同时列为多次登记的未证实候选，不能把候选量加总成更正量。折算待核对回报按证券保留，并未据此确认属于哪一次公司行为。

没有匹配候选的权益故障单独报告为证据缺口。材料始终标为仅检查；即使没有已记录故障，也不表示来源完整或取得解锁资格。已到账分红保留原现金入账证据，不自动生成新应收或重计现金。

导出示例：

```powershell
python scripts/run_offline_corporate_review.py --journal <合成账本路径> --output <复核材料JSON路径>
```

输出不能覆盖输入账本、SQLite附属文件、驱动/监督者锁文件及其文件别名。原183项相关检查之后，复查又补上批量登记字段重复、活动订单上下文重复、关联数量及导出字节上限的反例；本阶段共新增20个测试方法。最终检查及两份冻结源账本导出证据以`data/reports/etf_monetization_20260911/corporate_review_packet_stage/verification.json`为准。接下来进入补充成交证据协议，不改写旧回报或自动更正权益。

## 补充成交证据格式已实现

复核入口现可选用`--execution-evidence <合成补充证据JSON>`。文件上限100万字节、500条记录，拒绝重复JSON键、未知字段、非有限数值、过深嵌套和空值根对象。输入证据及其文件别名也受输出保护。未提供文件时保持原检查行为，不从旧回报生成已核实证据。

该格式只接收合成声明，分三层绑定：

| 层次 | 必需内容与校验 |
| --- | --- |
| 账本 | schema_version=1、offline_fixture_only、创世指纹、当前序号及事件链指纹；旧版本材料拒绝挂接到已推进的账本 |
| 原成交 | 原FILL或CONVERSION_UNAPPLIED_FILL事件的序号、指纹、订单和成交编号；禁止指向其他事件或拼接不同回报 |
| 来源及声明 | 唯一证据编号、来源/系列/消息编号、修订序号、前版引用、声称的原件SHA256；接收时点与成交时点分别表达，另列数量、价格及份额基准 |

接收时点必填，成交时点、数量、价格和原件指纹允许显式null，报告保留为未知。时间必须含秒和明确UTC偏移，拒绝无时区时间、未知偏移-00:00及成交晚于接收；不猜时间戳单位，不用本机入账时间补全。数量为正整数，价格为有限正十进制字符串。份额基准允许未知、未跨折算的原份额、某次折算前或折算后；后两者必须引用该证券冻结规则中实际存在的折算事件，前两者不能同时指定折算事件。价格基准仅表达未知或声称的原始成交价，不能输入复权收盘价代替成交价。这些字段校验仍不认证声明符合事实或适用时点。

每条来源系列从修订0的execution开始，correction或cancel必须完整引用同一原成交、同一来源系列的前一版本；重复身份、跳号、缺前版、分叉或接收时点倒退均拒绝。所有版本留在输出，不自动选择最后一版生效，也不生成现金、份额或费用更正。与原回报数量/价格的差异只列作数值差异，单位仍可能不同，不能当成经济差额。

输出绑定同一个只读账本视图，并为补充文件的规范化内容生成指纹；声称的原件SHA256没有经过文件或来源认证。即使字段齐全，来源真实性、成交归因、权益及结算依据、证据完整性仍未认证，原候选关联及缺口保留。新增18个测试方法，94项相关检查通过；已到账分红不重计，旧单位迟到回报不自动换算或应用。两份冻结现场的实际导出与最终打包检查见`execution_supplement_stage/verification.json`。

补充格式本身不执行更正。更正命令须另满足下节的完整事实、差额与事务要求；本格式不承担券商字段映射、认证或接入，不增加向前模拟天数或盈利成熟度。

## 更正事务的冻结验收契约

原有`paid`集合和一次性现金入账只适用于原始完整分红，不能表示补款、退款或多次结算。本阶段范围为**单项现金分红的合成更正与分次结算**，已完成的具体条件见末节。份额折算、成交撤销和跨多次公司行为的自动级联更正另列阶段。遇到后续权益依赖或证据不闭合时明确拒绝，不能为走通单项路径忽略依赖。

更正事实必须同时指明：当前账本序号/指纹、冻结事件及原登记事件指纹、完整更正后持有人份额、相关成交全部版本的明确处置、单位与实际成交时点、登记及净分红依据、已记录的全部结算流水。来源未核实或任一候选仍未知时不能成为真实更正依据；合成测试可以给定明确假设事实，但不得从补充文件的“字段齐全”自动升级为已认证事实。成交证据没有登记权利本身的证明力。

对同一持有人及冻结每份净分红d，先分别按原规则计算完整权益E旧=round(q旧×d)、E新=round(q新×d)，再求差E新−E旧。令S为该公司行为已有现金结算的带符号净额，则除息后的未结余额为E新−S；正数记应收、负数记应付。**权益修订本身现金变化为0**，只有明确的新结算流水才能改现金；入款为正、退回为负，同时抵减相应未结余额。除息前只修订待生效权益，不提前增加应收或重放除息价格基准。

| 固定合成反例 | 正确结果 | 被排除的算法 |
| --- | --- | --- |
| 原100份、改140份，每份0.6元，已到账60元 | 新权益84元，待收24元；修订时现金不动 | 当作84元重新到账，或立刻加现金24元 |
| 原100份、改60份，每份0.6元，已到账60元 | 新权益36元，待退24元；现金待真实退款流水再动 | 删除原入账或把应付隐藏为0 |
| 原1份、改2份，每份0.005元，逐持有人四舍五入到分 | 完整权益均0.01元，修订差额0 | 单独把新增1份取整成0.01元并追加 |
| 原1份、改2份，按0.5逐持有人上进位折算 | 完整新份额均1份，修订差额0份 | 对迟到1份单独折算后再加1份 |
| 先按0.5上进位、再按2倍折算 | 原1份最终2份；不能合并为一次比例1 | 省略每次公司行为的独立取整 |
| 某订单成交额从400元改160元，最低佣金假设5元 | 两次完整订单佣金均5元，费用差额0 | 按撤减成交比例退回最低佣金 |

已验证12个固定模型情景，包含增加、减少、归零、已付款、取整和两次折算；证据为`entitlement_adjustment_contract_stage/counterexamples.json`。其中折算情景直接使用当前冻结规则的计算函数。情景不是新单元测试方法，不计入502个累计新增方法，更不代表实际费率或盈利证据。

实施时保留原权益与原现金事件，追加独立的权益修订和结算流水，凭永久身份去重。相同身份及内容重送须返回原结果；相同身份不同内容拒绝；两个竞争修订只能有一个通过原账本指纹检查。现金、应收、应付及修订关系必须在一次事务内一致，重启、提交前失败和提交后重送不能部分应用。估值须扣除应付，结算仅在现金与未结余额间转移；账目更正单列，不能变成策略收益或重置历史风险高点。

解除暂停需单独验证每项权益故障均有对应完整处置，不能清除其他权益、估值、监控、未知订单、操作者停止或风险停止。第一阶段验收至少覆盖：除息前修订、未支付增加/减少、已支付补款/退款、分次结算及退款超过已入账的拒绝、重复/冲突身份、过期指纹、并发写入、提交中断、估值转移守恒和不相关故障保留。若现有状态结构不能表达负未结余额，应先补明确应付结构，不能靠放宽旧`paid`检查解决。

实现依赖已定位：`offline_order_state`负责有效权益、应收/应付与结算投影及公开快照；`offline_dividends`负责冻结规则下的命令校验；`offline_journal`负责追加事务和永久身份。还必须共同修改`offline_admission`的开盘权益与可用资金、`offline_portfolio_risk`的持续净值及`offline_valuation`的报告。应付既从净值扣除，也须从可用于新买入的现金中预留；只改报告或净值会留下退款资金被再次下单占用的漏洞。旧事件保持原字节并可重放，新增状态由事件推导，公开结构版本与旧检查入口的兼容性另设回归。

## 分次到账子步骤已实现

`OfflineOrderJournal.record_dividend_cash_installment`新增明确的合成分次入款入口，只允许支付日之后、正数整分且不超过当前已登记应收的金额。每次同一事务增加现金并减少应收，余额为0才记为已支付；没有新流水就不移动现金。使用独立的DIVIDEND_CASH_INSTALLMENT事件，旧完整入款事件和严格等于当前应收的旧接口语义保持。旧程序不识别新事件时会拒绝读取，不能将新分次事件伪装成旧全额事件；旧账本本身仍可由新代码重放。

新旧入款接口共用永久现金流水身份，重送不重复入账，身份冲突、提前到账、零/负值、分以下金额和超额入款拒绝。两个独立写入者竞争同一60元应收、各申请40元时，只有一笔生效，剩余应收20元；提交中途失败保留原现金、应收和去重状态。入款不清除监督者、操作者或其他已有故障，也不更改价格基准。复核导出保留每次分次入款事件。

该子步骤新增8个方法，235项相关检查通过；首轮估值样例复用了入款前账本指纹，被正确拒绝，已改为每次入款后重新取得估值上下文。持仓100份、原始估值3.4元、现金2,600元加60元应收的合成现场，在20元和40元分次到账过程中净值始终为3,000元，资金转移不计成收益。证据为`dividend_installment_stage/verification.json`；当时仅提供账本API，后续驱动、更正与退款范围见下节。

## 单项现金分红更正与退款已实现

新增`revise_dividend_entitlement`及`record_dividend_cash_refund`。更正事实绑定当前账本创世指纹、序号和链指纹，冻结分红政策指纹及原登记内容指纹，并完整列出已记录现金流水和全部迟到成交的来源版本与处置。份额必须与原登记加减已证明时点的迟到成交完全对应；成交数量、价格必须等于原回报，不在本入口撤改成交本身。来源明确标为assumed_offline_fixture，原件指纹只是合成事实的一部分，未做真实来源认证。

每条迟到回报必须选定唯一终版证据，明确成交时点、未跨折算的份额单位及原始成交价；是否计入登记按冻结截止时间核对。缺项、歧义、遗漏、数量无法解释、活动订单、已折算单位或后续已经登记的同证券公司行为均阻止单项更正。新的更正必须保留所有此前来源记录并追加修订，不能覆盖旧成交时间；同一登记原件指纹不能在不同修订中声称不同持有人数量，检查覆盖全部历史修订。

原登记份额和原入款事件不改写，有效权益由追加修订表示。除息前只更新待生效权益；除息后把有效净权益与带符号已结算额的差分成应收或应付，修订本身不改现金。应付同时从净值和新订单可用现金扣除，也参与发送前资金不足检查。退款必须引用当前修订，按正数整分提交，写成负向现金流水；不能超过应付或已结算净额。补款与退款共用现金流水身份，跨方向复用编号也会被拒绝。

修订和退款均在原追加事务中校验、写入和去重；相同请求跨重启重送不重复应用，竞争修订只能有一个通过原指纹。真实子进程在插入后、提交前退出时保留原账；提交后退出时重送不会重复改变现金或权益。估值单列当期已入账更正，标为需要重述绩效归因，保留原风险高点与停止状态。低精度调用环境下的预留误判已复现并修复，资金比较使用固定精度。
