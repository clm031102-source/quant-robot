# 冻结范围的来源采集入口

`scripts/collect_tushare_source_scope.py`已把受限HTTPS客户端接入实际命令入口。它用于CN_ETF来源资格审查，默认只预览；仍不切换默认SDK采集、不授予因子或收益读取额度、不连接券商。当前代码的日期上限固定为2025-12-31，2026 ETF留出继续封存。

## 执行顺序与证据

预览检查完整范围、引用文件指纹、所有请求及预算，不读取凭据、不运行网络请求，也不创建执行产物。执行必须传入预览给出的范围指纹；入口重新运行当前办公室/任务分支的Quant PM启动门禁，检查返回状态和阻断项，不能仅依据门禁进程正常返回。门禁通过后才读取现有`TUSHARE_TOKEN`，不购买权限。

每项HTTP请求之前，先保存具体请求和排他占用记录；失败后停止剩余批次，保留已尝试与未尝试数量。重启、改变范围名称、增加行数预算或调整字段顺序，都不会重复已经占用的同一请求。进程中断后不自动清除占用或恢复下载。该约束针对同一仓库的规范化相同请求，不是跨机器服务，也不证明不同日期范围、字段集合之间不存在重叠；改范围或删除记录不能充当新的研究授权。

产物固定保存在忽略目录`data/reports/tushare_source_collections/`：

- `runs/<范围指纹>/`保存范围、调用入口指纹、当次启动门禁、逐请求诊断、规范化来源投影及结果。
- `claims/<请求身份>.json`在请求前排他创建并刷新到磁盘；失败和未知中断都保留。
- 每个成功投影保留供应商标量类型、空值、重复行及可选分页字段。投影指纹与HTTP响应字节指纹分别记录，不能互相冒充；顶层非数据字段不在该投影中。
- HTTP错误、权限拒绝、范围/结构错误、空结果和采集后的文件写入失败有不同记录。空结果返回非零退出状态，不自动认证无事件。

真实响应重放发现，提供商还返回`has_more`与`count`。现已保留这两个可选字段；若`has_more=true`则明确失败，不自动翻页。四份现有响应均为`has_more=false, count=0`，实际行数分别为1087、62、184、14；因此不把`count`直接解释为实际行数或全事件数量。缺少分页字段也不会被补成“没有下一页”。

2026-09-21集成审查补上响应重复JSON键检查。此前默认解析器会保留最后一个同名字段，可能用后出现的`has_more=false`覆盖`true`，或覆盖提供商拒绝代码及整个`data`对象。现在任意对象层级出现重复键即以`response_schema`失败；保留请求占用、响应长度与原始字节指纹，不输出成功投影、不继续剩余请求、不重试。三个HTTP反例在修复前均复现错误接收，修复后及完整采集链路通过；HTTP、采集、CLI、日历和分红相关44项测试、87项子测试通过。全部使用合成响应，没有新增网络取件或研究授权。

## 范围文件与使用

范围JSON接受下列必选字段，以及下方说明的单日来源选项；不接受凭据、未知键或重复JSON键：

| 字段 | 合同 |
| --- | --- |
| `schema_version`、`scope_id` | 版本1；简短的小写英文、数字、下划线或连字符标识 |
| `purpose`、`primary_market` | 分别为`source_qualification`、`CN_ETF` |
| `max_date` | 明确YYYYMMDD，最晚20251231；每个请求和返回的范围日期还须满足自己的边界 |
| `trust_env` | 明确布尔值；false仅为本次直连，不改系统代理 |
| `max_response_bytes` | 正整数，每个响应至多2000000字节 |
| `connect_timeout`、`read_timeout` | 正的有限秒数，各不超过30；读取超时是单次网络读取等待，不是整批总时长保证 |
| `review_evidence` | 1至16条仓库内现有文件的`path`与`sha256`；指纹只绑定已审材料，本身不构成来源准入 |
| `requests` | 1至16项，每项只含`api_name`、`fields`、`max_rows`、`params`；每项最多10000行 |

原支持API为`fund_adj`、`fund_div`、`anns_d`、`etf_limit`。必须显式选择日期或封闭日期区间；基金分红只接受一个公告日、除息日或支付日，不能构造无限历史查询。身份、日期字段必须纳入请求，具体范围还受客户端校验。

后续[现金支付来源评审](cn_etf_cash_payment_pressure_review_2026-09-14.md)增加`dividend`的窄范围支持：每项必须是一只沪深A股加一个`imp_ann_date`，不接受全市场、年度、区间、支付日或预案日查询。强制保留预案/决案日、实施日、进度、分红年度、登记/除息/支付日、两种现金口径及基准日/股本；返回日期逐项核对截止日，允许非实施日字段为空并保持未知。7项新增、31项相关测试通过，包含收集后禁止重复执行；不继承为来源认证或研究准入。

之后的一次单日覆盖小样增加可选布尔值`allow_dividend_market_day`，省略时为false、保留上述窄范围。只有显式true时，范围必须恰好包含一个`dividend`请求，参数必须只有一个`imp_ann_date`，最多2000行；不能同时指定公司、混入其他接口、多日或区间。追加2项、累计9项新增和33项相关测试通过。该请求范围可能包含沪深A股以外代码，返回后仍需身份、币种和事件口径审查；不会自动成为市场现金或因子。

新增`trade_cal`仅用于完整日历来源：参数必须恰好为`exchange,start_date,end_date`，交易所仅SSE/SZSE，一次封闭区间最多366个自然日，且行数预算足以覆盖；字段必须恰好为`exchange,cal_date,is_open,pretrade_date`。禁止开市日过滤。返回必须覆盖每个自然日且不重复，严格核对开闭市值和前交易日链；首日前驱的区间外真实性仍待外部依据。来源行序和类型保留，日历校验模块纳入实现指纹。11项新增、48项相关测试通过，六份真实年度日历的限定核对见[早期历史资格审查](cn_etf_fixed_exposure_history_review_2026-09-14.md)。

先对实际已冻结文件运行预览，再在获准来源范围内使用其指纹执行：

```powershell
python scripts/collect_tushare_source_scope.py --scope <范围文件.json> --machine office_desktop --branch <当前任务分支>
python scripts/collect_tushare_source_scope.py --scope <范围文件.json> --machine office_desktop --branch <当前任务分支> --execute --expected-scope-sha256 <预览指纹>
```

目前已将本轮之前完成的6次权益来源请求，以及1次明确公告权限拒绝，按旧范围/结果指纹导入占用记录；这7项不能因换用新入口而重跑。导入没有新增请求，也没有认证全部历史探测都已迁移。四项扩展范围的实际命令预览能识别4项已经占用。
