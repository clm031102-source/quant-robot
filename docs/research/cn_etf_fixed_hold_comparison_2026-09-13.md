# 同资金、同日历的固定持有对照

固定持有对照已接入现有模拟命令。它从声明的初始现金开始，按照预先指定的份数、买入价格上限和排列顺序，在第二个观察日尝试一次买入；之后保留持仓与闲置现金，不额外生成因子、自动再投资或重试未成交订单。当前验收全部为合成数据，不是新策略、净正EV或真实向前交易证据。

## 已实现的账户与比较规则

`src/quant_robot/paper/fixed_hold.py`复用原有模拟成交、整手、最低佣金、容量、权益与逐日估值函数。初始资金只计一次；不通过预装持仓增加总资产。份数明确为入场日公司行动之后的单位，入场前后已持有份额的折算由原权益账本处理。

现金分红先形成应收，到所声明发放日收盘后才成为现金；毛额事件仍被账户拒绝。未成交、现金限制下的部分成交、停牌、容量不足和价格超过上限分别记录。后续价格导致日损失、持仓金额或回撤超过声明限制时，记录超限；持续估值不会凭空补出一次止损成交。

`src/quant_robot/paper/account_comparison.py`从账户权益重算收益，检查双方完整日期、起始现金、实际请求与嵌套费用声明、公司行动指纹及已报日收益的一致性。初始权益必须等于全部初始现金，不能附带未支付的持仓或应收；理论指数曲线不能充当现金账户。当前现金对照明确为零利息情景。

默认风险观察条件是单仓1000元、日损失60元和回撤8%；入场限制与持续持有超限记录分别输出。费用一致、资金相同仍不代表市场风险相同，因此比较结果始终保留`risk_adjusted_alpha_verified=false`，来源、研究准入和完整执行条件也不由本接口认证。

## 现有模拟命令如何使用

在已适用的`run_paper_simulation`命令上添加`--fixed-hold-benchmark <声明文件>`。声明文件只接受版本和入场清单；以下是合成测试用法，不是某只ETF的实际订单建议：

```json
{
  "schema_version": 1,
  "entries": [
    {"asset_id": "CN_ETF_XSHG_510300", "quantity": 100, "limit_price": 10}
  ]
}
```

对照自动继承策略的初始现金、佣金、最低费用、滑点、冲击、容量和同一权益文件，不能在清单里另设一套资金或费用。只支持从现金开始的CN_ETF账户，要求明确容量及权益声明。策略与对照使用同一组实际模拟日期，预热行情不加入对照计息天数。

输出包含`fixed_hold_benchmark.json`、其逐日权益CSV及`account_comparison.json`；主清单同时保存比较结果与入场清单的文件指纹。有对照产物时使用新输出目录，避免后续普通模拟留下上次对照文件。

真实行情入口的准入检查仍在行情和清单读取之前执行，未新增绕过选项。合成演练可直接运行：

```powershell
python scripts/run_cn_etf_fixed_hold_drill.py --output-dir data/reports/cn_etf_fixed_hold_drill_new
```

这个演练没有真实数据输入选项；输出目录已存在就拒绝覆盖。现有模拟命令的完整参数及实际子进程流程也已由集成测试覆盖。
